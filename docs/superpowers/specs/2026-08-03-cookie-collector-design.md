# 曲奇收集器 (Cookie Collector) — Edge 插件设计

日期: 2026-08-03

## 目标

一个 Microsoft Edge 扩展(Manifest V3)。当用户在网站上点击"接受 Cookie"按钮时,页面上掉下一块曲奇动画,并累计收集数量,可在工具栏弹窗中查看、吃掉或清空。

## 用户流程

1. 用户访问任意网站,网站弹出 Cookie 同意横幅。
2. 用户点击"接受/同意/Accept"等按钮。
3. 插件识别该按钮 → 页面上从顶部掉下一块曲奇(SVG 图形,带旋转 + 下落动画,约 1.2 秒后消失)。
4. 曲奇计数 +1,持久化到 `chrome.storage.local`。
5. 用户点击工具栏图标 → 弹窗显示:总曲奇数、"吃掉一个曲奇"按钮(计数 -1,累加到"已吃掉")、"全部清空"按钮。

## 架构与组件

纯前端扩展,无后端。四个组成部分:

| 组件 | 职责 |
|------|------|
| `manifest.json` | MV3 清单,`storage` 权限,content_scripts 注入 `<all_urls>`(仅 `document_idle` 注入 content.js) |
| `content.js` | 页面内:检测 Cookie 接受按钮、触发曲奇动画、上报计数 |
| `popup.html/js/css` | 工具栏弹窗:显示计数、吃掉曲奇、清空 |
| `icons/icon{16,32,48,128}.png` | 曲奇图标,用 PowerShell + System.Drawing 生成 |

## content.js 详细设计

**按钮识别:**
- 关键词列表:
  - 中文:`接受`、`同意`、`允许`、`我知道了`、`确认`、`好的`
  - 英文:`accept`、`agree`、`ok`、`got it`、`allow`、`i understand`、`fine`、`sure`
- 匹配逻辑:按钮/链接/带 role 的元素的文本(全小写后)包含任意关键词,即视为目标。
- 减少误报:优先匹配位于弹窗容器(常见类名如 `cookie`、`consent`、`gdpr`、`modal`、`banner`、`dialog`、`notice`,或 `position: fixed` 且尺寸小于视口 80% 的容器)内的按钮。若容器判断失败,退化为页面级匹配(仅文字关键词,允许少量误报)。
- 动态页面:MutationObserver 监听 `childList` + `subtree`,新节点加入时重新扫描。

**触发方式:**
- 每个匹配按钮绑定 `click` 监听器(直接绑定,不使用委托,避免事件在 shadow DOM 内的差异问题;若按钮在 shadow DOM 内则无法直接命中,此项为已知限制,不处理)。
- 点击 → 执行曲奇动画 + 计数 +1。

**曲奇动画:**
- 在页面创建一个 `position: fixed` 的容器 div,注入内联 SVG 曲奇(data URI 或内联 SVG 字符串)。
- 动画:从 `top: -80px` 的随机水平位置落下,旋转 360°+ 随机角度,1.2s 后淡出并移除 DOM。
- 每 500ms 最多触发一次动画(节流),防止连点导致大量 DOM。

**计数上报:**
- `chrome.storage.local` 存储结构:`{ total: number, eaten: number }`。
- 写入失败(如浏览器扩展页、无 storage 权限场景)时静默降级为内存计数,不报错。
- 注意:content script 在 `chrome://` 页面不被注入,天然跳过。

## popup 详细设计

- `popup.html`:展示 SVG 曲奇 + 总数,两个按钮("吃掉一个曲奇"、"全部清空"),以及"已吃掉"数量。
- `popup.js`:读取 storage → 渲染;吃掉 → `total-1, eaten+1`;清空 → 两者归零。storage 变更事件 `onChanged` 同步刷新。
- 样式:`popup.css`,简洁卡片风格,固定宽度 ~280px。

## 错误处理

- storage 读写异常 → 内存降级,不抛错、不打断用户页面。
- 动画容器创建失败 → 忽略,仅计数。
- 页面为 `data:` 或 `file:` 等受限上下文时无动画,不影响页面功能。

## 测试

- 手动测试(无自动测试框架):
  1. 本地起一个测试 HTML,内含中文/英文 Cookie 弹窗按钮,验证动画 + 计数。
  2. 用 `--load-extension` 或 Edge 扩展页加载未打包扩展。
  3. 验证 popup 吃掉/清空逻辑。
  4. 验证刷新页面后计数持久化。
  5. 验证在百度/必应等真实网站点击 Cookie 横幅按钮。

## 明确不做的(YAGNI)

- 不自动点击"接受"按钮(必须用户自己点)。
- 不处理 shadow DOM 内的按钮。
- 不做设置页、不做徽标(badge)计数。
- 不做多语言 i18n 目录(按钮匹配词硬编码)。

## 新增功能:食物关键词点击(2026-08-03 追加)

- 点击页面任意位置元素,其自身或祖先(最多向上 3 层)的文本(去首尾空白后 ≤100 字符)包含食物关键词 —— 曲奇、曲奇饼、饼干、小甜饼、cookie、biscuit(英文不区分大小写,自然覆盖 cookies 等变体)—— 即掉落曲奇并计数 +1。
- 与"接受 Cookie 按钮"识别并存:点击时先匹配按钮(原逻辑),再匹配食物词;命中其一即触发,一次点击最多触发一次。
- 共享原有 500ms 节流窗口(连点不重复计数)。
- 已知限制(预期内):长文本(>100 字符)段落中的关键词不触发;点击超大容器(如整个 body 的空白处)不触发;点击单词元素或短容器(按钮/链接/短标签)正常触发。
